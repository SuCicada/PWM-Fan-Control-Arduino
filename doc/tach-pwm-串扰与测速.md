# TACH 测速：PWM 串扰与软件滤波

一次现场现象的完整记录。风扇调速一直是对的，错的是 RPM。

## 现象

| 占空比 | 真实观感 | 读数 |
|--------|----------|------|
| 100% | 全速，正常 | ~1400 RPM |
| 50%（第一版，`CHANGE` 中断） | 转速听着正常 | ~190000 RPM |
| 50%（第二版，下降沿 + 500µs 去抖） | 同上 | ~30000 RPM |
| 50%（第三版，1ms 稳电平轮询） | 同上 | 回到合理区间 |

指令生效、PWM 输出都没问题。只有测速在「PWM 会翻转」的占空比下炸。

## 根因

四线风扇两根信号线挨着：

- **PWM**（Pin 9 / Timer1）：25kHz，周期 40µs。占空比 0% 或 100% 时引脚几乎不翻转；中间占空比时是方波。
- **TACH**（Pin 3）：开漏，每转 2 个脉冲。1400 RPM 时脉冲频率大约 47Hz，低电平持续数毫秒。

PWM 边沿通过电容耦合 / 共地 / 平行走线窜进 TACH。MCU 看到的不是干净的转速方波，而是「真脉冲 + 25kHz 毛刺」。

所以 100% 正常：PWM 不翻转，TACH 干净。50% 爆炸：PWM 每秒翻 25000 次，边沿中断全算进 `pulseCount`。

公式：

```
rpm = counts * 60000 / (COUNTS_PER_REV * elapsed_ms)
```

`elapsed_ms ≈ 1000`、`COUNTS_PER_REV = 2` 时，每秒多计 1000 次脉冲 → 读数 +30000。和现场对得上。

## 为什么前两版治不好

### 边沿中断本身就是错的入口

毛刺每个边沿都进 ISR。`CHANGE` 双边沿更惨；改成 `FALLING` 只是少一半，25kHz 仍是每秒两万多次中断。ISR 里再聪明，CPU 先被打满了。

### 「最小间隔去抖」对连续高频噪声无效

直觉：真实 tach 间隔至少几毫秒，短于 500µs 的当毛刺丢掉。

对**偶发尖峰**成立。对**一直在的 25kHz** 不成立——去抖不会消掉噪声，只会按死区把它**降采样**：

```
允许通过的最大频率 ≈ 1 / 500µs = 2kHz
→ 换算 RPM ≈ 2kHz * 60 / 2 = 60000
```

现场 30000 就是这个降采样后的假转速。把死区改成 5ms 也一样：假转速变成「看起来还挺像风扇」的几千转，更难发现。

一句话：**间隙去抖滤的是尖峰，不是载波。**

## 做法：不要数边沿，数「稳住的电平」

关掉 TACH 中断。主循环里轮询，同一电平稳住 1ms 才承认一次翻转，只在稳定的下降沿 +1。

```
读到的电平变了     → 重置计时，什么都不算
同一电平还没满 1ms → 继续等
满 1ms 且相对上次稳定值是下降沿 → pulseCount++
```

两个时间尺度差了两个数量级，所以能分开：

| 信号 | 周期 / 脉宽 | 过得了 1ms 稳定门吗 |
|------|-------------|---------------------|
| PWM 串扰 | 40µs | 过不了，计时器不断被重置 |
| 真 TACH | 低电平数毫秒（1400 RPM 约 10ms） | 能过 |

实现见 `src/fan.hpp` 的 `pollTach()`。`TACH_STABLE_US = 1000`。

调速后要 `resetTachWindow()`：旧窗口里的计数和稳定状态作废，避免切占空比那一下把脏数据算进下一秒。

## 代价和边界

- 靠主循环采样。`loop` 平时很快（微秒级），25kHz 毛刺会被连续看到、稳定门过不去。`Serial` 打印会堵住十几毫秒，最多漏一个真脉冲，约 30 RPM 误差，可接受。
- 若风扇 tach 脉宽本身短于 1ms（极高转速或很窄的脉冲），会少计。PC 风扇一般到不了这个区。
- 这是软件滤波。线在模拟域耦合足够狠、把真脉冲也切碎时，稳电平同样认不出来，RPM 会偏低或归零。那时要硬件：TACH 加 RC、和 PWM 分开走线、共地处理好。

## 对照现场的三次读数

```
100%  ~1400     真转速（PWM 不翻转，无串扰）
50%   ~190000   CHANGE 中断把 25kHz 边沿全算上
50%   ~30000    500µs 去抖把 25kHz 抽成 ~1kHz
50%   合理      1ms 稳电平：毛刺过不了门，只留真脉冲
```

## 以后怎么查这类问题

1. 先看读数是否**随 PWM 占空比爆，而不是随实际转速变**。0/100 正常、中间炸 → 优先怀疑串扰，不是风扇坏了。
2. 逻辑分析仪同时盯 PWM 和 TACH：50% 时 TACH 上有没有 25kHz。有分析仪的话第一版就能定性，不用猜三次。
3. 传感器滤波要想清楚噪声形态：尖峰用死区；载波用稳定门或低通；别用「最短间隔」去滤一直存在的高频。
4. 被噪声污染的脚不要挂边沿中断。
